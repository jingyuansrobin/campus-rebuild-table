# V3 v0.2 — Campus Search + Automatic Project Creation

## Goal

Implement the first user-facing input step for V3 without copying the V2 search architecture.

```text
search university
    ↓
select campus candidate
    ↓
automatically create CampusProject
```

The desktop GUI is still deferred. CLI commands are the executable development surface for this slice.

## V2 audit

V2 proved several useful implementation details, but the search path is not migrated as-is.

### Keep as experience

- reject blank searches;
- tolerate malformed individual POI records instead of failing the whole result set;
- validate coordinates;
- deduplicate repeated POIs;
- preserve the external POI ID and anchor coordinate so later boundary editing can start from the selected campus.

### Rewrite

- network transport;
- university filtering;
- candidate domain model;
- project creation hand-off;
- error surface.

### Drop

- using the embedded map/WebView as the search transport;
- the `Idle → Searching → Candidates → Detail → Confirmed` UI state machine in core logic;
- mandatory detail-page confirmation before selection;
- accepting the whole `1412` school family (middle school, primary school, vocational school, etc.);
- generating a project/campus ID inside the search adapter.

## V3 design

Search uses AMap Web Service from Rust. Map rendering remains a separate concern for v0.3.

The request asks AMap for higher-education POIs (`typecode 141201`) at the source instead of retrieving broad school results and filtering them later.

```text
CLI / future Desktop
        ↓
GaodeSearchClient
        ↓
AMap Web Service
        ↓
CampusCandidate[]
        ↓
Application Core
        ↓
CampusProject + RealityModel
```

`CampusCandidate` is provider-neutral domain data. The Gaode adapter owns AMap-specific parsing and request construction.

## Configuration

The CLI reads the AMap Web Service key from:

```text
AMAP_WEB_SERVICE_KEY
```

Keys are runtime configuration and must never be committed to the repository.

## Acceptance criteria

1. Search rejects blank keywords before any network request.
2. Requests restrict results to higher-education POIs (`141201`).
3. Malformed coordinates are skipped; valid candidates remain usable.
4. Duplicate POI IDs are returned once.
5. Explicit campus suffixes such as `华东师范大学(普陀校区)` are represented as school + campus label without losing the exact display name.
6. Selecting a candidate can create a local `CampusProject` through Application Core.
7. `reality.json` records the source POI ID, display name, address and anchor coordinate.
8. Existing project data is never overwritten.
9. Network/API errors do not expose the configured API key.
10. CI remains green without making live AMap requests.

## Deferred

- desktop search UI;
- interactive map rendering;
- polygon boundary editing;
- search suggestions/autocomplete;
- ranking personalization;
- overseas campus providers.
